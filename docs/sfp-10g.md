# Selectable 1G / 10G SFP switch port

`KR260_SFP_MODE=1g` is the default, retaining the existing 1000BASE-X MAC,
PCS, GTH configuration and 16-bit switch interface. `KR260_SFP_MODE=10g`
selects the separate `ghlhub.org:ethernet:sfp_10g_port:1.0` MAC/PCS, a
10.3125 Gb/s GTH and a 128-bit SFP switch interface. Selection is at build
time; changing a register cannot switch the serial protocol.

The 10G configuration passes local simulation, synthesis and routed timing
under the current constraints. It has not been deployed or qualified with the
purchased XZS-SFP10G-RTL-T module. The known-good running image remains 1G.

## Build

Use Vivado 2026.1 and fresh output directories:

```sh
python3 scripts/verify_ip_flow.py --sfp-mode 10g \
  --vivado /tools/Xilinx/2026.1/Vivado/bin/vivado \
  --output build/ip_refactor/acceptance_10g --implement
```

Use `--sfp-mode 1g` for the default image. The flow generates a catalog,
validates the production BD, runs native and staged IP tests and the existing
1G regression, then optionally implements and reports timing/CDC. The 1G
production/native equality miter is deliberately not applied to 10G: its
reference has a different wire protocol and datapath width. The 10G checks
use packet scoreboards, wide-buffer/forwarding regressions and the actual BD
wiring audit. This distinction is recorded in `results.json`.
An implementation-stage failure after a constraints-only correction can be
resumed with the same arguments plus `--resume-implementation`. This rechecks
the catalog against current RTL and audits the BD before reusing completed
simulation gates; previous failure logs remain in the report directory.
RTL changes require a fresh acceptance directory.

For a direct build, first package a fresh catalog with `ip_repo/package.tcl`,
then set `KR260_IP_CATALOG`, `KR260_PROJECT_DIR` and `KR260_SFP_MODE=10g` when
running `build/build_kr260.tcl -tclargs bd|synth|impl`. Use separate project
and catalog paths for each variant. The build script recreates its project
directory. Both catalog IPs are available; only the selected one is instantiated.

## Datapath and physical shell

- GTH X0Y6 uses the existing KR260 SFP pins and 156.25 MHz reference. Its new
  vendor core is reproducibly generated by `rtl/sfp_10g/ip/create_gth_10g.tcl`
  using the 10GBASE-R asynchronous 64b/66b gearbox preset. TX and recovered RX
  have separate 156.25 MHz clocks and reset-release synchronizers.
- The MAC adds/removes preamble and FCS, pads short TX frames, checks received
  FCS and drops bad/overflowed frames in a frame FIFO. The PCS scrambles,
  encodes/decodes 64b/66b, acquires block lock, monitors BER and requests GTH
  realignment or datapath reset. The watchdog reset pulse crosses to the
  50 MHz reset controller using a toggle synchronizer.
- XGMII reconciliation qualifies local/remote fault ordered sets, sends remote
  fault on local receive failure, sends idles on remote fault, and gates link
  status and packet transmission. Fault and link status are registered in the
  RX domain before synchronization into TX/management; reset removes link
  admission even if the RX clock stops. Four matching ordered sets qualify a fault;
  128 columns without fault sequences clear it.
- Port 4 alone uses 128-bit AXI-Stream at the 125 MHz fabric clock, including
  ingress RAM, header extraction and egress RAM. Other physical ports and the
  CPU remain 16-bit. The fabric parameter is `SFP_DATA_WIDTH=128` (default 16).
  The DDR packet format, allocation, reference counting and forwarding masks
  are unchanged. Wide ingress rejects zero/sparse keeps, partial non-final
  beats, error-marked frames and frames exceeding its 2048-byte buffer.
- Async MAC frame FIFOs bridge 128-bit fabric traffic and 64-bit XGMII. Their
  upstream Gray-pointer/data-ownership constraints and status synchronizers
  are applied by `constraints/kr260_sfp_10g_cdc.tcl` before `opt_design`.
  This is a full Tcl hook, not an XDC `source`/conditional. The 1G build instead
  loads its original clock-pair bounds from `kr260_sfp_1g_cdc.xdc`.

The 128-bit path removes the old 2 Gb/s SFP interface ceiling. It does **not**
make the shared store-and-forward fabric a nonblocking 10G switch. A single
frame per port, shared DDR arbitration, small frame FIFOs and slower egress
ports limit sustained throughput. Congestion can drop whole RX frames; the
MAC currently does not implement PAUSE/PFC. No 10G line-rate throughput claim
is made. Standard untagged 1514-byte frames are the intended traffic; jumbo
frames and tagged-frame policy are not qualified.

## Firmware and registers

The control address remains `0x800C0000`; RX enable at `+0x404` and TX enable
at `+0x408` retain bit 28. AW and W are accepted independently, byte strobes
are honored, and responses remain valid under backpressure. Other legacy 1G
MAC configuration registers are not emulated: reads return zero and writes
are ignored.

| Offset | Read value |
| --- | --- |
| `0x404` | RX enable in bit 28 |
| `0x408` | TX enable in bit 28 |
| `0x4F0` | Host rate, 10000 Mb/s |
| `0x4F4` | Bit 0 block lock, bit 1 PCS RX health, bit 2 high BER |
| `0x4F8` | Core ID `0x31304745` |
| `0x4FC` | ABI version 1 |

The legacy `an_*` pins carry operational link/full-duplex/fault state; there
is no Clause 37 autonegotiation in 10GBASE-R. Management still receives these
signals through the board's existing SFP status path. Firmware detects the
core ID and reports 10000 Mb/s while linked. **This is the host SerDes rate,
not the copper speed negotiated inside an RJ45 module.** One firmware image
works with both FPGA variants. Saved `Auto` selects the installed host rate;
a forced 1G/10G selection admits the port only when it matches that build.
The configuration API advertises `[0,1000]` or `[0,10000]`, and the web page
labels unsupported rates even when the physical link is down. Build with:

```sh
make -C software/r5 -j8 STATS_DDR=1 STATS_DEBUG=1
```

The statistics mailbox retains its eight-slot ABI, but the 10G counters measure
RX delivery to the fabric and TX enqueue into the MAC FIFO, excluding FCS.
RX discarded-frame events come from FIFO bad-frame/overflow status; bytes of
frames discarded inside the MAC are unavailable. TX enqueue counts are not
proof of successful wire transmission. Standard statistics thresholds still
classify frames above 1514 bytes as oversized. MAC AXI interrupts are tied low;
CPU AXI DMA interrupt operation is unchanged.

## Module qualification still required

The vendor's [rate-matching module page](https://xzsnet.com/pages/sfp-10gbase-t-rm)
describes a fixed 10GBASE-R host with multiple copper speeds, but the purchased
`XZS-SFP10G-RTL-T` revision has not been matched conclusively to that datasheet.
That rate-matching datasheet’s stated maximum power exceeds the KR260 cage budget described in
[UG1092](https://docs.amd.com/r/en-US/ug1092-kr260-starter-kit/Powering-the-Starter-Kit-and-Power-Budgets).
Confirm the exact module power and host-interface specifications before board
qualification. Lower copper rates and any required PAUSE-based rate matching
need separate implementation/qualification; they are not supported by this
initial 10G configuration merely because the module can negotiate them.

Simulation covers MAC/PCS loopback, FCS corruption/drop, block-lock recovery,
AXI backpressure and independent AW/W, fault qualification/recovery, wide
buffer tails/ownership/drops and MAC learning/forwarding with the SFP width
selected. It does not model the analog transceiver, cage power, cable loss,
module firmware or board signal integrity. The existing external RGMII timing
budget and broader reset/CDC review items remain open.

## Local verification (2026-09-28)

- `build/ip_refactor/sfp1g_compatibility/results.json`: default production BD,
  native and packaged IP tests, four counter-option regressions and the
  production/native assembly equality check pass.
- `build/ip_refactor/sfp10g_acceptance/`: separate 10G production BD; all 35
  native and 35 packaged IP tests and all four existing native regressions pass.
- `make -C software/r5 test`: passes, including host-rate detection and saved
  admission policy for both variants. HTTP test fakes now include the existing
  IPv4 snapshot/formatting calls so the full HTTP suite builds.
- R5 all-counter build and ELF memory/vector checks pass. Browser tests pass
  with 1G and 10G capability responses, including a disconnected 10G port.
- Imported dependency files match every pinned provenance SHA-256. The 1G
  clock-pair constraints exactly match the previous default constraint set.

The final source rebuild is `build/ip_refactor/sfp10g_final/results.json`:
fresh catalog/hash audit, native and packaged MAC/PCS/fault tests, board build
and routed review all pass. This rebuild registers fault/link status before
CDC and adds stopped-RX-clock reset coverage. The four new fault-status CDC-10
findings are gone; those crossings are now reported as CDC-3 synchronized
single-bit paths. All reported FIFO bus-skew constraints pass.

Final setup WNS is **+0.018 ns**, hold WHS **+0.010 ns**, with zero failing
setup/hold endpoints. The bitstream is
`build/ip_refactor/sfp10g_final/project/kr260_switch.runs/impl_1/kr260_top.bit`.
`software/r5/out/kr260_r5.elf` is the matching all-counter firmware; the result
JSON records SHA-256 hashes for both artifacts.

This is not blanket CDC or physical-interface sign-off. Methodology reports
retain six asynchronous-reset LUT warnings (including GTH reset qualification),
eight missing I/O delays and the existing broader CDC/clock-review items.
The external RGMII budget remains provisional. Hardware traffic, module power,
interoperability and sustained throughput qualification remain outstanding.

Runtime switching is available separately with `KR260_SFP_MODE=dual`; see
[the dual-rate implementation](sfp-dual.md). That image has now demonstrated
basic 1G forwarding and a hot swap to an XZSNET copper module with a 10G host
link through a 2.5G-capable switch. It has not established loss-free operation,
actual copper negotiation, or sustained rate-matching throughput. The fixed
`10g` build described here retains its original behavior and was not deployed.
